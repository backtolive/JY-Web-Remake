# ADR 0040：DOSBox-X state 載入需先驗收

2026-11-13。Status: Accepted for current DOSBox-X 2026.10.01 test build。

## 背景與證據

使用者指出可用 Save/Load state 快速回到測試起點。這是正確的目標，但現有 `docs/validation/dosbox-x-debugger-and-sampling.md` 已記錄 SDL2 同程序儲存 slot 2 後載入即崩潰，以及 slot 1 冷載入崩潰，兩次均有 `Loaded. (Slot N)` 日誌及 Windows `0xc0000005` 事件。SDL1 同程序 slot 3 亦曾在載入後退出。`Loaded.` 不能當作可操作復位。

## 決定

現階段不把 DOSBox-X emulator state 當作已驗證的快速復位。新的測試可優先用**原版遊戲內的讀檔**或可證明一致的其他同程序方式；必須核對載入後場景、事件槽、背包與至少一個遊戲畫格，才能批次沿用。若使用 emulator state，先在隔離案例證明載入後程序仍存活、鍵盤可操作、記憶體狀態與存檔點相符，再宣稱可用。

本輪從遊戲內 Esc 選單觀察到「醫療／解毒／物品／狀態」四項；五次 Down 高亮回到第二項，Right 沒有開啟第二頁。此路徑尚未找到讀檔入口，不能因社群引擎有「系統／讀取」選單就當作原版此頁存在。

## 後果

之前每案重啟的成本是真實限制，需優先修復或替換；但未驗證的 state 載入會遺失當前程序並可能混淆事件證據。隔離第三槽資料仍在結束程序後以六檔 SHA-256 還原，原始資料不變。

## 已驗證的同程序替代路徑

事件 936 首場戰鬥失敗後回到原版讀檔選單，沿用 PID 7508；此時先還原原第三槽，再準備事件 49，於同一個視窗選第三槽，唯讀確認載入的主角 HP 999、攻擊 1000 與事件 ID 49。其後在仍同一 PID 的主選單以 `Reset virtual machine`（即時解析 command ID 4096）返回原版標題，程序和 HWND 均未變；準備事件 676 的第三槽並用原版讀檔、唯讀確認事件 ID 與五件物品。這證明**同程序切換測試案例**可行；它是原版讀檔／虛擬機重置，不是會崩潰的 emulator state restore。重置後仍須等標題穩定、只送足夠的入場 Up，並驗證事件真的被觸發。

事件 101 的勝利案例再次沿用 PID 7508，結束後以同程序 `Reset virtual machine` 回標題，再還原第三槽六檔 SHA-256。啟動腳本 `Start-DOSBoxX-IsolatedEvent.ps1` 原本在錯誤處理區塊直接 `Stop-Process`；現已改為保留仍存活的程序和隔離存檔現場，回報待還原狀態。只有程序已結束時才自動還原存檔，避免錯誤時擅自關掉遊戲視窗。
