# ADR 0049：通用決策事件的第一個可續行切片

日期：2026-11-16。狀態：採用第一個切片；尚未取代既有 v0.1 遊戲 Runtime。

## 決策

在 `game-core` 增加獨立、版本化的 JSON 事件內容與執行介面。事件步驟只接受 `say`、`choice`、`decide`、`end`。`decide` 使用 ADR 0048 的 JSON 決策計畫，狀態含玩家目前位置、通用決策狀態和可序列化事件游標。每次 `START`、`CONTINUE` 或 `CHOOSE` 命令在複本上執行；對話與選項是明確的暫停／保存邊界。命令後段失敗時不回傳複本，也不改動傳入狀態。

新內容經 Schema、對話引用、選項目標、選項 ID 和命名空間驗證；解析後資料凍結。新存檔使用 schemaVersion 2、Runtime `0.2.0`、依內容 ID／版本／SHA-256 區分的獨立 Web key，綁定同一內容身分。讀回時先驗證格式及精確內容身分，再驗證決策領域、不變量與暫停游標。主存檔寫入前先驗證，舊主檔保留備份。v0.1 內容與存檔完全沿用原有路徑，未暗中轉換或覆寫。

Mock 案例已驗證：初始 3 個道具，事件說話後等待選項；保存並讀回，選擇付款後扣 2 個道具、加入同伴、設旗標與下一事件綁定，事件結束。選擇另一選項不改決策狀態；道具不足、錯誤選項、內容版本不符及畸形存檔均拒絕，舊狀態與主檔保留。

## 範圍與下一步

這是獨立的 Mock 決策事件內容與存讀切片，尚未接到目前 Web 畫面、原版 1,018 個事件、原版事件槽覆蓋層、地圖碰撞或完整遊戲存檔。位置目前只做格式驗證，沒有地圖引用／可通行性驗證。它只涵蓋對話、選項與資料決策；戰鬥、動畫、切圖、隨機及其他等待外部結果的流程仍需受控命令與續行結果契約。完整存檔還必須合併地圖、角色、戰鬥、MOD 鎖定、隨機種子與原版事件槽；版本升級須提供預檢與備份遷移，不得把此 Mock save 當成完整原版存檔。

下一步先把受控命令／結果與完整狀態契約定義清楚，再整合 Web 與原版內容轉接器。原版 opcode 只有證據驗收後才能映射；未知指令拒絕受影響事件。
