# ADR 0042：opcode 55 分支歸因須有實際執行路徑

2026-11-14。Status: Accepted for Phase 1／2 research。

原版 DOS 中的合成事件可提供輸出差分，但道具增加／未增加本身不等於已證明解譯器採用某個比較分支。客體記憶體快照可定位事件資料與候選跳轉表，但靜態位置也不等於實際命中。opcode 55 的 `-1` 比較尤其需要分開處理：28 次原始出現皆使用 `-1`，先前合成輸出尚有二進位路徑歸因落差。

故在完成可重現的命中時 CS:EIP、游標與參數 trace 前，保留合成測試的輸出事實，將「相等／不相等跳轉」降為 Inferred；不得據此轉換全部原始事件，亦不得把候選二進位處理段標為 Verified Original。已明確驗收的其他 opcode 不因此重測或阻塞。證據與還原紀錄見[限定追查](../validation/opcode-55-binary-trace-20261114.md)。

追加觸發守門：搜尋事件槽必須先錨定**不隨動畫改變的欄位**；圖號變動使全紀錄匹配失敗，不等於腳本已執行。沒有道具／狀態／腳本載入等正向證據時，斷點未命中只記為「本輪未到該位置」，不淘汰候選 handler。見[前置追查](../validation/opcode-55-trigger-preflight-20261114.md)。

正向觸發後已於合成事件 1017 實測 `0160:001E1ADF` 入口與 dispatcher 游標運算；本案 helper 返回 `-1`，腳本索引由 0 最終到 4。這驗收**該案例的執行路徑**，不把先前道具輸出的相等／不相等歸因或原始 28 次 `-1` 案例一併升格。見[單點 trace](../validation/opcode-55-verified-entry-trace-20261114.md)。

其後原始事件 464 的四次 `55` 亦全部命中同一 handler，均返回 `-1`，並讓腳本索引淨前進四字。基線 KDEF 的 28 次 55 均具有同形五字參數及後續 word 3。故可把**事件 464 的這四次游標效果**列為 Verified Original，其他 24 次仍只有靜態 bytes 同形證據；不得把社群版條件判斷當作本 DOS 版本的已驗規則。見[原始事件 trace](../validation/opcode-55-original-event464-trace-20261114.md)。
