# ADR 0039: 以可逆合成存檔與不停模記憶體觀察採樣原版事件

Date: 2026-11-12
Status: Accepted for this investigation

## Context

原版事件 676 需要事件 460→675 的前置鏈。DOSBox-X emulator save state 可保存但 SDL1／SDL2 載入均曾崩潰；原版遊戲內的世界地圖存檔可正常讀寫。場景入場條件及室內位置限制手動重播，且進度一不證明自然可到達目標事件。使用者已允許修改隔離存檔副本並以只讀記憶體／畫面核對，要求完成原版指令驗證。

## Decision

- 保留 `original/dos` 及進度一檔不變。所有介入只用隔離 `session-002/game` 的第三槽，變更前複製 R3/S3/D3 六檔、記錄 SHA-256、byte offset 和 before／after；合成狀態明標 Synthetic State。
- 每次新啟動先以提升權限確認不存在另一個 `session-002` 程序，再綁定唯一遊戲 HWND／PID／完整標題。冷啟動須確認標題頁；每個依賴的選單轉換有畫面或雜湊證據。異常先觀察，不繼續盲送鍵。已知按鍵間隔至少一秒。
- 以 DOSBox-X 內建 raw screenshot 擷取單一遊戲畫格，不用桌面全屏；以原版遊戲內存檔核對持久欄位。室內無法存檔的當下，可以對**精確已確認的 DOSBox-X PID** 使用唯讀 `ReadProcessMemory` 找候選紀錄，遊戲保持執行。搜尋命中須以操作前後變化、原始結構及畫面交叉確認；host address 隨程序變更，不視為 guest 固定偏移。
- 候選記憶體紀錄即使名稱或前綴 bytes 唯一，也要先核對原版段界與**多個相鄰記錄的姓名**。事件 581 曾沿用社群 208-byte 角色間距而誤把「黃蓉」當成角色 49「虛竹」；原版實為 182-byte 間距。錯位讀數不得用來否定能力或入隊指令。之後還需至少一項隨同一操作變動的欄位、原版存檔差分或限定 trace 才提升信心。
- R3 開頭的隊伍 bytes 可在 DOSBox-X 內存作為**載入存檔副本**出現，事件完成後仍保留舊值。事件 581 中唯讀搜尋完整六人序列另找到更新為 `[0,49,-1,-1,-1,-1]` 的執行中紀錄。之後評估入隊／離隊時，同時檢查這兩種副本；不得把單一未變的候選地址當作執行中隊伍。
- 把「原版指令在合成前置狀態下的執行結果」和「該狀態在自然遊戲流程可達」分開驗收。合成入場／背包只能支持前者。複合事件中的分支指令與後續扣物品／給物品效果也分開標記。
- 複合事件重播前，確認世界圖載入完成、場景入場條件與室內事件格的位置。按鍵送達不代表已入場或腳本已觸發；若畫面或事件欄位沒有預期變化，先檢查精確遊戲畫格與已載入的場景／事件紀錄，再調整路線，不把失敗嘗試當 opcode 的負面證據。
- 對話／選項／物品通知屬同一事件的不同暫停點。讀取最終記憶體前，確認所有覆蓋層已消失且後續腳本已完成；事件中途的隊伍或背包值僅記為中途狀態。對固定場景可用 `tools/analyzer/classify_dosbox_game_frame.py` 對乾淨畫格計算覆蓋區像素差，先輸出文字狀態；若場景切換、差異接近門檻或有未知 UI，才人工檢視單一遊戲畫格。這是自動化狀態守門，不是 OCR 或指令語意證據。
- 固定場景的多段對話可用 `scripts/Advance-DOSBoxX-DialogueUntilClear.ps1`：開始時須有覆蓋層，每次 Enter 後只記錄本機分類器的文字結果，首次消失後再等三秒確認仍消失，然後才讀取最終記憶體。達到步數上限或覆蓋層重現即停止並人工檢查；不能僅憑 Enter 次數判定事件完成。
- 目標指令後若接戰鬥等另一種 UI，讀到的角色數值只能標為中途狀態。事件 28 的戰鬥選人框被分類器回報為覆蓋層，須查看該張遊戲專用畫格確認流程已離開對話；不得沿用對話推進腳本繼續送 Enter。
- 冷啟動標題選單按鍵若送得太早，可能把「讀取進度」誤選為「重新開始」。事件 115 初次測試停在「請輸入姓名」且目標事件未載入；此時立即停止、檢查精確畫格、關閉並還原。重試時先確認標題頁與三槽載入頁，再選第三槽並唯讀核對事件槽。方向鍵間隔至少一秒；可能切場景的 Enter 後等三秒再判讀。
- 標題頁分類失敗不可當作成功。opcode 31 首次試跑的 720×400 啟動文字頁與 640×400 標題參考圖尺寸不符，分類器報錯後 PowerShell 的空結果曾通過數值門檻；現在先檢查分類器結束碼與非空結果，再決定是否送鍵。異常畫格已檢視，該試跑未進入遊戲事件。
- 批量首輪僅將「原始候選事件已載入與觸發」記為覆蓋，不將它等同目標 opcode 已執行或語意已驗證。首輪腳本先比對 640×400 標題與三槽頁，再核對目標事件 ID；原版前置若要求使用物品、選項、戰鬥、長對話或音訊，記錄未達原因並留待專案專用流程。錯誤進入姓名頁、候選位址不唯一或無法辨識頁面時，關閉唯一程序、還原第三槽，不產生 opcode 結論。
- 已確認的 opcode 不因換一個事件再重跑；後續 DOS 採樣集中於 Unknown 或有具體矛盾的案例。已知標題選單與進場按鍵可連續執行，每鍵間隔至少一秒；只在新使用者指示後、必要里程碑或異常時檢查當前狀態。
- 模擬器 state 載入在本環境曾崩潰，不作目前事件重播前置；只有確認修復且同 build／同 config 成功讀回後才恢復使用。這是對 ADR 0038 所述「已知 checkpoint 時讀取 state」的實測例外。

## Consequences

事件 460→675→676 可在單一隔離副本重播，並能透過存檔及不停模記憶體核對部份狀態變化；每一結論只覆蓋實際測到的參數與路徑。未測的 opcode 和自然可達性維持 Unknown，不能因社群來源或成功解析長度而提升為 Verified Original。
