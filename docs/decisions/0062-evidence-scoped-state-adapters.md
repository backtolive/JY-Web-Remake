# ADR 0062：依事件證據限制狀態轉接，不先建立通用 opcode handler

日期：2026-11-20。狀態：Phase 3／6 局部採用。

在事件 673、581 之後，已有數個 DOS 前後值足以建立狀態效果，但不足以定義所有參數變體。採用來源鎖定的事件案例 adapter：每個案例綁定 KDEF／RANGER 雜湊、事件記錄雜湊、指令 word offset、確切參數、採樣前值與容許改動欄位。案例可以共用狀態容器，但不能因 opcode 編號相同便對其他事件開放。

本輪加入：事件 289 的角色 36 五欄及兩種性別前置；事件 28 的角色 4 用毒；事件 101 的主角聲望；事件 497 的主角品德與前五格背包視窗；事件 950 移除角色 1；事件 932 清除兩名同伴。事件 289 的角色切片可序列化、恢復及拒絕污染；其他小型 adapter 保留不可變輸入與精確前置。

另建立 ALLSIN 場景 layer 稀疏覆蓋容器，保留來源雜湊並以 `scene/layer/cell` 鍵原子更新；第一個案例是事件 274 將場景 32、layer 1、陣列格 `(12,22)` 從 `0` 寫為 `2898`。座標仍使用 `arrayIndex1/arrayIndex2`，不推定成世界 X/Y。

後續加入 RANGER 84×52-byte 場景紀錄 overlay，以及更多精確案例：事件 420 將場景 75 offset 18 `1→0`；事件 821 的已掃描集合為場景 2／4／38／75 `1,1,1,1→2,0,2,1`；事件 434 在明示 Synthetic State 下把單一 layer 格 `990→994`；事件 353 的槽 4／5／6 欄 4 `-1,-1,0→0,0,1`；事件 567 的槽 8 欄 5–7 `0→6448`。事件 821 未掃描全部 84 場景，因此 adapter 只保存四筆已觀察值。

事件 676 僅保存 DOS 實際觀察的前九格背包視窗：前四格維持，格 4–8 的 138–142 各 1 變為 `176×1` 與四個空格。這能驗證該正例交易，不等於完整背包容器，也不將 opcode 50 的分支或 opcode 2／32 其他參數升格為通用規則。

事件 20／931 使用 prepared-role adapter，先從不可變 RANGER 基線顯式建立 DOS 採樣前值，再套用 MP `26/26→0/26` 或 HP `1/44→44/44`。原始基線分別是 `25/25`、`32/32`，不得把採樣存檔數值改寫成內容包原值。

這些 adapter 不是完整事件執行。事件中的對話、戰鬥、場景槽、地圖層、動畫、音訊或其他尚未一起核對的效果不能省略後宣稱事件完成。正式 Runtime 遇到未支援部分仍須停止整筆事件且不提交部分狀態。總矩陣以 `scoped event-… adapter; not generic` 區分於 `not implemented` 和完整通用支援。
