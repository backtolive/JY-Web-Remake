# ADR 0059：事件 581 的槽位差分僅作來源鎖定的段落比對

日期：2026-11-19。狀態：Phase 1／2 證據複核、Phase 3 限定投影；未建立通用 opcode 3 規則。

全事件靜態清單顯示 opcode 3 的候選參數形狀 `-2,+,0,0,-1,-1,-1,-1,-1,-1,-2,-2,-2` 出現在 106 個事件。選事件 581 是因為已有[單人／滿隊 DOS 前後紀錄](../validation/opcode-20-dos-observation.md)，可以核對新形狀而不再重複執行已觀察的路徑。

`tools/extractor/compare-original-event-581-slot.mjs` 鎖定原始 `KDEF.IDX`、`KDEF.GRP`、`ALLDEF.GRP` 雜湊，以及事件 581 KDEF byte 88988、106 bytes、記錄 SHA-256。候選 word 15 的 `3(-2,2,0,0,-1,-1,-1,-1,-1,-1,-2,-2,-2)` 投影至場景 32／槽 2 的欄 0–7；原始表為 `[1,2,-1,-1,-1,2718,2718,2718,0,30,21]`，投影後為 `[0,0,-1,-1,-1,-1,-1,-1,0,30,21]`，與單人隊伍 DOS 採樣後值相符。滿隊採樣中槽位維持前值。這些是**段落前後比對**，沒有把參數形狀直接提升為其他 105 個事件的轉換規則。

本案 opcode 3 前有 opcode 14，後有 opcode 0、13；紀錄沒有在各指令之間凍結讀取。因此欄 0／1 與圖像欄 5–7 的歸因仍需隔離對照；原本就是 `-1` 的欄 2–4 更不能用未變的結果證明「寫入」或「保留」。通用原版事件 Runtime 不新增此形狀的執行支援。下一個有意義的證據是保持相同前置與原始腳本，對其中一個待辨欄位設不同前值並觀察指令段前後，必要時在 opcode 3 周圍取得精確執行點；不必重測 106 個事件。

後續已有[單指令合成腳本隔離對照](0060-isolated-opcode-3-shape581.md)：確認這組參數對欄 0／1、3／4、5–7 的效果；本 ADR 原本的段落比對結論保留作當時證據邊界。
