# ADR 0048：通用狀態決策契約先於原版 opcode 映射

日期：2026-11-15。狀態：採用架構；決策核心第一個切片已實作，完整遊戲流程尚未接入。

## 決策

通用引擎以**版本化、可驗證的 JSON 決策契約**處理資料狀態，而不是為每個原版 opcode 增加一個遊戲特例。內容包先宣告狀態領域、值型別、預設值、範圍、清單上限、合法 key 清單及可選的合法成員／事件值清單；跨領域不變量亦可用條件表示，例如目前生命不得超過生命上限。條件可比較常數或不同狀態引用，做 `all`／`any`／`not`、數值大小與清單包含。效果可指定值、加減數值、增減有序清單成員及中途斷言；第一個符合條件的分支執行，另有明確的其他路徑。

每次決策在舊狀態的複本上執行，全部條件、型別、範圍、預算及最終狀態驗證通過後才回傳新狀態與逐欄變更清單。失敗拋錯，不回傳部分狀態。事件、道具、角色或 MOD 的原始 ID 由內容包與轉接器映射為命名空間 key；通用引擎不認識 DOS 欄位或特定人物。

| 需求 | 結構化表示 |
|---|---|
| 道具數量與屬性值 | 整數領域；`compare`、`add`、`set`，範圍由領域宣告 |
| 特殊旗標與任務條件 | 布林或字串領域；`compare`、`set`、複合條件 |
| 隊伍成員 | 有序清單領域；`contains`、`listAdd`、`listRemove`、人數／唯一性上限 |
| 事件綁定與場景狀態 | 命名空間字串、布林或數值領域；內容轉接器負責原版槽位映射 |
| 多條件分支、連續更新 | `cases` 首條命中、`otherwise`、同一交易內依序效果與 `require` |

例如「有兩個道具、指定成員在隊且攻擊力達標，扣兩個道具並改下一事件」可以全用 JSON 的條件及效果表示；測試中的 Mock 計畫已實際執行這種組合。結構定義在 `packages/game-core/src/decision-schema.ts`，匯出的四份 Schema 在 `schemas/decision-*.schema.json`，執行核心在 `packages/game-core/src/decision.ts`。

簡化的 Mock 計畫示例（合法領域和 key 須先由內容包宣告）：

```json
{
  "schemaVersion": 1,
  "cases": [{
    "when": {
      "op": "compare",
      "left": {"kind": "read", "ref": {"domain": "mock:inventory", "key": "mock:item/medicine"}},
      "relation": "ge",
      "right": {"kind": "literal", "value": 2}
    },
    "effects": [
      {"op": "add", "target": {"domain": "mock:inventory", "key": "mock:item/medicine"}, "amount": {"kind": "literal", "value": -2}},
      {"op": "set", "target": {"domain": "mock:bindings", "key": "mock:scene/32/slot/2"}, "value": {"kind": "literal", "value": "mock:event/paid"}}
    ]
  }],
  "otherwise": []
}
```

## 邊界與擴充

這套契約覆蓋**已宣告的資料狀態決策**；不能憑空保證未知遊戲機制都只需改欄位。戰鬥、選人、對話、動畫、切圖、隨機事件與需要等待外部結果的流程，仍須使用受控、可續行的命令及明確結果型別。未來每個新命令必須有版本化 Schema、引用與權限驗證、執行預算、存檔續行點及測試；內容 JSON 不得執行任意宿主程式碼。

既有 `game-core` v0.1 內容包與存檔維持原契約。新決策核心目前是獨立 v1 子契約，尚未接到現有 `Step`／`GameState` 或原版 1,018 事件；整合時須升級內容／存檔版本並提供相容性預檢及備份遷移。原版 opcode 的映射仍依來源 bytes 和 DOS 證據逐功能驗收，未知指令必須拒絕受影響事件且不提交部分狀態。

## 完整涵蓋的驗收條件

「可支援所有遊戲狀態變更」須以可檢查的條件驗收，不能只依架構宣稱：

1. 原版實際使用的每個 opcode、每種參數形狀都能映射到已宣告狀態交易或受控特殊命令；未映射者列出事件 ID／來源偏移並拒絕執行。
2. 道具、角色屬性、隊伍、旗標、場景／事件槽、戰鬥、位置、隨機種子及續行點都在同一完整存檔與版本相容性驗證內。
3. 每條可達劇情分支的條件、前後狀態與可見結果有原版證據或清楚標示其他來源；從開場到結局能本機重播。
4. 獨立原創內容包不修改通用核心也能定義同類狀態與劇情；MOD 依賴、衝突、載入順序及存檔版本可確定解析。

目前只達成「資料決策核心與 Schema」的第一段，以上完整驗收仍待後續工作。
