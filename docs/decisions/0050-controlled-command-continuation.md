# ADR 0050：受控命令的結果與續行邊界

日期：2026-11-19。狀態：採用局部契約；Mock 事件已驗，原版流程未接入。

## 決策

在 ADR 0049 的 v1 事件切片旁新增獨立的 **v2 事件內容、v3 存檔**。舊內容與存檔仍由舊 Runtime 讀取，不暗中轉換。v2 事件除了 `say`／`choice`／`decide`／`end`，可用 `invoke` 暫停並發出版本化請求。首批受控外部命令為戰鬥、動畫、切圖與選人；對應結果有封閉的 JSON Schema。`roll` 為內部加權分支，使用存檔內的明確亂數種子，不要求外部任意提供隨機結果。

`invoke` 的請求包含腳本位置與遞增序號組成的 `requestId`，並存入游標的 `pending`。結果只帶請求 ID、命令種類和有限的結果值。引擎檢查請求 ID／種類／允許結果後，選取**內容包已宣告的**結果分支；結果本身不能攜帶任意 `effects`、座標或宿主程式碼。戰鬥勝敗、選人等分支的狀態變更由 ADR 0048 的決策計畫執行。切圖目的地亦來自內容請求，外部僅回覆完成。

每個暫停點都是可保存的提交邊界。進入等待前的狀態已提交；處理 `RESOLVE` 時在複本上套用結果決策、位置與後續步驟，全部通過才回傳。後段失敗會保留舊的待處理請求，供檢查或重試；過期、重複、種類不符及未宣告結果拒絕。完整存檔包含內容 ID／版本／SHA-256、玩家位置、決策狀態、事件游標、待處理請求、序號與亂數種子。Web 使用由精確內容身分區分的 v3 key，保留前一份主檔備份。

四份 Schema：`controlled-command`、`controlled-result`、`controlled-event-content`、`controlled-event-save`。Mock 測試覆蓋戰鬥勝利後的道具／旗標更新、動畫、切圖、選人、跨暫停存讀、錯誤結果拒絕、後段決策失敗不提交、固定種子重播與畸形內容拒絕。

## 限制與後續

這仍是**獨立 Mock 切片**，未與目前 Web 遊玩畫面、地圖通行驗證、原版事件槽覆蓋層、戰鬥規則或完整原版存檔合併。引擎目前只接收外部戰鬥結果，尚未計算勝負；動畫及切圖只驗證回覆，沒有渲染器或場景載入協定。亂數分支為通用機制，不代表已核對原版機率。v3 save 不含 MOD 清單／規則集完整鎖定，也沒有 v0.1／v2 的自動遷移。

下一階段先把外部命令交給實際 Web 宿主並做精確結果回報，再整合原版內容、地圖／角色／戰鬥與完整存檔。任何原版 opcode 只有逐功能證據支持後才能映射；未知指令停止受影響事件。
