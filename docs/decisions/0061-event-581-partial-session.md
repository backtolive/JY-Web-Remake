# ADR 0061：事件 581 的來源鎖定局部工作階段

日期：2026-11-20。狀態：Phase 3／6 限定切片；不是完整原版事件 Runtime 或遊戲存檔。

[ADR 0060](0060-isolated-opcode-3-shape581.md)確認一組事件 581 opcode 3 參數對場景 32／槽 2 欄 0–7 的效果。為了驗證這項效果能安全進入可存讀流程，新增 `original-event-581-session.mjs`。工作階段只容許三種狀態：已驗隊伍採樣前的 `ready`、單人隊伍完整效果提交後的 `completed`，以及六人滿隊且狀態不變的 `blocked-full-party`。單人完成後隊伍由 `[0,-1,-1,-1,-1,-1]` 成為 `[0,49,-1,-1,-1,-1]`；滿隊樣本為 `[0,1,2,3,4,5]`。這些是 DOS 實際採樣，不解讀成通用 opcode 10／20 規則。

完成交易同時提交三個領域：事件槽八欄、角色 49 的八個已歸因 int16 欄位，以及六格隊伍。人物欄位為 HP／MaxHP `38→238`、MP／MaxMP `21→321`、攻擊 `14→44`、速度 `30→50`、offset 80 `1→2`、武功 ID offset 128 `0→15`。offset 42 的 `90→92` 因來源未隔離而刻意不寫；武功等級與其他 byte 也保持來源值。任何額外角色 byte 或 overlay 記錄都使恢復失敗。

原始資料的自然安裝鏈也納入來源鎖：擂鼓山場景 53 初始槽 0 為事件 533，候選動態寫入依序為 `533→534→536→581`，最後將事件 581 安裝到槽 2。原始事件層的槽 0 位於陣列座標 `(28,16)`，槽 2 位於 `(18,24)`；這些座標保留 `arrayIndex1／arrayIndex2` 名稱，不推定成未驗證的世界 X／Y。

靜態來源另確認事件 536 word 160 起的 52 words 與事件 581 終止符前的完整 body 逐 byte 相同。這只允許共用來源識別，不證明 536 該分支自然可達，也不驗證其後三筆場景 28 寫入與 `8(3)`；因此本工作階段不執行那些效果。

序列化資料鎖定 KDEF／ALLDEF 來源雜湊、事件記錄雜湊、指令 byte offset 與完整參數。恢復時重驗內容鎖、前置、槽位值和 overlay 範圍；執行時先驗證舊狀態，再建立新的不可變 overlay，重複執行或任何污染都在提交前拒絕。

此格式 `original-581-slice` 只保存本案例的事件槽、角色 49、六格隊伍及自然引用位置。道具、戰鬥、事件 533／534／536 的其他效果、規則集與 MOD 身分仍需納入正式完整存檔；不得將此切片視為原版存檔互通或完整劇情可玩。
