# 原版 DOS 解譯器的 opcode 55 分支對照

2026-11-14。Phase 1／2；Status: **一般正數事件 ID 的比較及跳轉局部確認，`-1` 特例未解**。先前原始事件 464 的兩組前值都產生相同後值，見[未解紀錄](opcode-55-unresolved-dos-observation.md)。本輪保留原始程式與原始 KDEF，在 ignored 的 `session-002/game` 隔離副本，把固定長度 26 bytes 的事件 1017 暫時換成 Synthetic Script；原版 DOS 解譯器仍由同一 DOSBox-X PID 7508 執行。原始 `KDEF.GRP` SHA-256 `135c5e097a7fe561ee931046e1bebf55de9b469678e3d111d8e9f2c6bb600e06`，事件 1017 原段 SHA-256 `d4a349215b38f7f14a913aab14367064f0e46b728ae79fff321e1c277094c6aa`。每版 patch 都在 ignored manifest 備份、記錄前後雜湊；測後已還原整個 KDEF 及六檔隔離存檔。

合成腳本只有 `55(2,比較值,相等跳轉,不相等跳轉)`、`2(57,1)`、`7`、終止填充；跳轉 3 個 word 會略過給道具指令，跳轉 0 會執行它。每案都從原版遊戲讀取隔離第三槽，唯讀確認場景 32 槽 0 指向事件 1017、槽 2 的事件 ID 前值，互動後讀取**活躍**背包與原版道具提示。場景／事件指向和腳本內容均明確標為 Synthetic State／Synthetic Script，不能當成原始事件 1017 的自然劇情。

反向跳轉組顯示**輸出會隨合成腳本中的兩個偏移參數配置改變**。比較值與槽值同為 581 時沒有取得道具；`0` 對 `0` 和 `-1` 對 `-1` 時取得道具。這是輸出事實；「選到相等／不相等跳轉」與「非正數不走相等」是當時的解釋假說，尚未取得執行游標證據。[後續客體記憶體追查](opcode-55-binary-trace-20261114.md)找到候選跳轉表，但未在候選入口停住，故不能把假說升格為原版語意。其他負數未驗：準備 `-2` 存檔時被事件 ID 範圍檢查擋下，沒有執行，已還原該版合成 KDEF。不能把社群版 `DData[scene,slot,2] == value` 直接當成原版對所有值成立。原始語料的 **28 次 opcode 55 比較值全部是 `-1`**，所以這個差異對原始事件轉換很重要；精確比較欄位及負值處理仍待限定 trace。原始事件 464 的先前觀察與本輪 `-1` 結果一致，但不因此改寫原始事件腳本或通用引擎規格。`0` 案測後已還原整個 KDEF 與隔離第三槽，PID 7508 未變。

後續[正向觸發單點 trace](opcode-55-verified-entry-trace-20261114.md)修正對本表的解讀：`-1/-1`、`3/0` 合成案例命中 handler 時，堆疊兩個回傳候選皆為 `-1`，dispatcher 索引落在 word 4 的 `0`。上表的兩個「跳轉」欄位是合成腳本的配置標籤，尚未證明原版對其分支選擇；道具輸出事實保留。
