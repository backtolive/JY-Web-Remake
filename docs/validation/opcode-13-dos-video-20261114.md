# 原版 DOS 事件 935 的暗場與亮屏影格

2026-11-14。Phase 1／2；Status: **opcode 13 所在段有局部 DOS 影像證據**。原始事件 935 位於 `KDEF.GRP` byte 112750，長 56 bytes，SHA-256 `89cf7fb76f5364015155e38efef971d94266024a559277c8828316a31f57cb85`。候選正路是 `4(189,1,0)`、`1(2848,81,0)`、`0`、`14`、`3`、`0`、`13`、結束。原始 KDEF 未改。

在隔離第三槽合成場景 32 事件 935 與 ID 189 ×1，使用原版物品欄第五格選取該物品；同一 DOSBox-X PID 7508、遊戲 HWND `0x38085A` 唯讀確認事件槽為 935。Left、Enter 後原版畫格 `z_1207.raw1.png` 顯示台詞。關閉對話時錄製原生 `z_006.avi`，SHA-256 `0b90ebf5975ea9cfdc054ef6c9ad6a90dd155eeccb66219d828ed94d86cd38c3`；解碼 1887 幀。錄影第 1640 幀的全畫面平均 RGB 約 65，第 1650／1660／1670／1680 幀分別約 56／28／7／1，第 1690–1770 幀為 0，第 1790／1800／1810／1820／1830／1840／1850 幀分別約 1／4／10／21／33／46／66。唯讀同址場景槽 0 由事件 935 變為禁用 `-1`，符合中間 opcode 3 的預期。

原版在此路徑明確呈現**暗場後逐幀亮屏**；亮屏位於候選 `0,13` 最後一段，社群 `instruct_13` 也描述逐步亮屏，但社群說法只作比對。這支持 opcode 13 的局部亮屏語意；`0` 與 `13` 相鄰、沒有指令級 trace，故不能把精確幀邊界或所有畫面變化單獨歸給 `13`，也未驗其他事件路徑。先前只有前後穩定畫格而無中間影片的[限定採樣](opcode-13-44-65-bounded-20261113.md)仍保留。

隔離入場與物品前置是 Synthetic State。原生 AVI、解碼 PNG、manifest 均在 ignored `assets/generated/dosbox-x/`；不提交商業素材。測後在同一 PID 內重置虛擬機回標題，依 manifest 還原第三槽六檔 SHA-256，視窗仍開啟。
