# 原版事件 464：四次 opcode 55 的執行路徑

2026-11-14。Phase 1／2；Status: **事件 464 的四次 `55` 游標效果已取得 DOS 執行證據；其他事件與其他比較值未逐案驗收**。原始 KDEF 未修改（SHA-256 `135c5e097a7fe561ee931046e1bebf55de9b469678e3d111d8e9f2c6bb600e06`）；事件 464 位於 byte 71352，長 210 bytes。僅以 manifest 備份的隔離第三槽將場景 32 槽 0 指向此原版事件。使用 DOSBox-X 2026.10.01 的同一 PID 7508、遊戲 HWND `0x38085A`。合成入場不代表原版自然進度。

從標題讀第三槽，`Up` 進場後唯讀確認槽 0 的事件 ID 464。設定唯一 `BP 0160:001E1ADF` 並送 `RUN` 啟用，再 `Left`、間隔 1 秒、`Enter`。第一個停點 `CS:EIP=0160:001E1ADF`，`EBX=0x1C`（腳本 word 索引 28）、`EAX=0x38`（對應 byte 索引 56）。客體 `0x0028EE90` 事後含原始事件 464 的 210 bytes；首個 55 起始為 `55,2,-1,14,0`。回傳停點 `0160:001E1AF6` 的堆疊四參數 `[2,-1,-1,-1]`，`EAX=0xFFFFFFFF`（signed -1）。`0x001E1516` 後 dispatcher 將 `EBX` 加 5，再在 `0x001E14E9` 加上 `EAX`，所以此例從 word 28 到 word 32（28+5-1），落在 `0`，下一 word 33 是事件修改指令。

持續只在同一 handler 入口與 helper 返回點之間切換單一斷點，量到四次完整序列：

| 次數 | 入口 `EBX`（word） | 入口 `EAX`（byte） | helper 回傳 signed | 計算下一 word | 後續事件槽 ID |
|---:|---:|---:|---:|---:|---:|
| 1 | 28 | 56 | -1 | 32 | 槽 2 → 862 |
| 2 | 47 | 94 | -1 | 51 | 槽 3 → 863 |
| 3 | 66 | 132 | -1 | 70 | 槽 4 → 864 |

四次入口與返回的 `EV CS EIP EAX EBX ESP` 均在停點讀取；第二次後因 PowerShell 守門比對的是多行輸出，提前終止**控制腳本**，guest 當時停在第三次入口，並未關閉或重啟 DOSBox-X。修正輸出比對後從該停點接著完成第三、四次。最後 `BPDEL 0`、`BPLIST` 空、`RUN`，唯讀核對四個活躍事件槽值；guest 回標題，依 manifest 還原六檔第三槽。R3／D3 SHA-256 回到 `aa2f4dee1b6b73120ebe92a100535e30c7d608cb0d2b0dd38ffa900d9f47c22c`／`8ec61fa55fcdf698223534753b19e453f7d14f9510c3361ef4641e53ffec9d56`。DOSBox-X PID 7508 留在標題。

客體 handler bytes 顯示它把腳本 `word2` **重複送為兩個返回候選**，而不是把本案例的 `14` 與 `0` 作為這兩個候選。與[合成案例單點 trace](opcode-55-verified-entry-trace-20261114.md)相同，本原版事件的比較 word 為 `-1`，helper 回傳為 `-1`。因此事件 464 中四次 `55` 都表現為**五字指令後再退一字**；先前把「四個槽都被修改」解釋為某個相等／不相等分支，現在不再採用。這是指定原版二進位及事件 464 的證據；尚未逐項檢查其他 24 次出現的活躍執行路徑，亦未驗證其他參數值或 helper 額外副作用。轉換器若要處理原版 28 次 `55`，應先用此游標規則核對各事件的靜態後續 word，再以必要的原始案例驗收；不得直接套用社群 `判断事件编号` 描述。

以既有 `docs/research/fishedit-layout.local.json` 的版本化五字候選寬度，唯讀掃描**基線 KDEF**：28 次出現在 9 個事件 `10,32,95,286,303,464,466,511,513`；全部的 `word2=-1`、`word3=14`、`word4=0`，緊接 `word5=3`，只有 `word1`（目標槽）不同。這是 bytes 結構證據，不是另外 24 次的 DOS 執行證據；它使事件 464 的游標規則可對應到整批同形資料。此掃描不改 KDEF，也沒有重播已確認的其他 opcode。
