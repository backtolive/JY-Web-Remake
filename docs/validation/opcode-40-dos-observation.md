# 原版 DOS 事件 931 的主角朝向變化

2026-11-13。Phase 1／2 局部原版執行證據，重新分析 2026-11-12 已擷取的原版遊戲專用畫格，**沒有重跑已驗證的選項或 HP 指令**。原始事件 931 位於 KDEF byte 112604，SHA-256 `f5041f4174e01ca6a5bda54567e9ef84032cec75200cd634848b8e2d18c5d072`。Y 路徑依候選切分依序經 `14`、`12`、`40(3)`、`0`、`13`、第二段對話。KDEF 未改。

`z_399.raw1.png` 是選 Y 前的詢問畫面；主角在櫃檯前顯示側／背向站姿。`z_401.raw1.png` 是第一段對話結束、HP 已恢復且第二段對話開始的畫面；主角站姿改為面向畫面。以同一組 640×400 原版 raw PNG 比較，主角所在矩形 `(270,130)–(319,218)` 有 38.59% 像素顏色差異，鄰近未覆蓋背景 `(340,140)–(390,220)` 為 0%。兩張圖的不同不是整個場景位置或縮放變動。

該段候選指令中，`40(3)` 是唯一明示主角站立圖／面向參數的項目；本案例支持它在 Y 路徑切換主角朝向。畫格只能確認輸出姿態變了，沒有獨立讀到原版內存朝向欄位，不能單憑圖像證明數值 `3` 對應哪個方向，也不能排除後續 `13` 負責把已改的姿態重畫。其他參數與自然流程可達性未驗。畫格與隔離存檔來源詳見[事件 931 原始觀察](opcode-11-12-dos-observation.md)。
