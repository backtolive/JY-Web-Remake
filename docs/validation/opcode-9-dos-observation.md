# 原版 DOS 事件 96 的加入選擇

2026-11-12。Phase 1／2，局部原版執行證據。原始事件 96 位於 KDEF byte 16618，長 100 bytes，SHA-256 `a327bd81850f5961c43c60630e0fd5e3af8187ce9692912a89fba7a7d6a592b8`。候選前綴為 `1(373,16,0),0,9(6,0)`；KDEF 未修改。

隔離 `session-002` 第三槽將場景 32 槽 0 映射為原始事件 96，合成解鎖入場，兩案的前置狀態相同。原始首段對話後顯示「是否要求加入（Y/N）」（`z_441.raw1.png`）。選 N 顯示主角婉拒對話（`z_442.raw1.png`）；選 Y 顯示主角答應同行對話（`z_446.raw1.png`）。因此本案例支持 opcode 9 讀取 Y/N 並選擇不同後續對話。兩句對話分別由後續 opcode 1 呈現，不是 opcode 9 自身的文字。

N 案的執行中隊伍維持 `[0,-1,-1,-1,-1,-1]`。Y 案在答應對話期間及關閉後的下一個畫格顯示「得到胡青牛醫書」通知（`z_447.raw1.png`），當時隊伍仍為同值、場景 32 槽 0 已由後續腳本改為 `-1`。**Y 案截在物品通知，並未跑到腳本終點**；因此不能推論最終是否有人加入，也不能把物品或事件槽效果歸於 opcode 9。本案只確認選擇分支；後續角色加入效果另需驗證。

變更原值、byte offset、SHA-256 及備份見 ignored 的 `synthetic-op9-event96-no-20261112/manifest.json`、`synthetic-op9-event96-yes-20261112/manifest.json`。兩案在關閉唯一精確 DOSBox-X 程序後還原第三槽，六檔 SHA-256 均回到基線。未驗證 `6,0` 的完整相對跳轉公式、其他事件的參數變體及自然可達性。
