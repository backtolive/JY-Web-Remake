# 原版 DOS 指令 60 的事件圖號分支

2026-11-12。Phase 1／2，局部原版執行證據。原始事件 990 位於 KDEF byte 116694，長 120 bytes，SHA-256 `79c9e1a77ed7ba6dfa7dc9c42c13fbaaf23ca8f5da968e09a28fa3507caf3d40`；開頭候選為 `60(80,1,6068,0,21)`。KDEF 未修改。原始第三槽來源中，`D3.GRP` 場景 80／事件 1 位於 byte 352022，圖號欄位 5／6／7 均為 6068。

兩次 DOSBox-X 2026.10.01 測試都以 Synthetic State 將場景 32 的 NPC 槽 0 指向原始事件 990、解鎖入場，並在隊伍槽 1 放入角色 58。第一案保留場景 80／事件 1 原圖號 6068；第二案只將其三個圖號欄位改為 6066。兩次均確認世界圖轉入室內、事件 990 腳本載入，並從相同位置互動。改動、原值、offset、SHA-256、備份記於 ignored 的 `synthetic-op60-event990-pic6068-20261112`、`synthetic-op60-event990-pic6066-20261112` manifest。

| 場景 80／事件 1 圖號欄位 | 原版畫格 | 局部結論 |
|---|---|---|
| 6068／6068／6068，來源原值 | `z_412.raw1.png`：請楊兄先回「神雕宮中」。 | 走原值對話路徑。 |
| 6066／6066／6066，Synthetic State | `z_417.raw1.png`：請楊兄先回「古墓」。 | 走另一段對話路徑。 |

這支持 opcode 60 在事件 990 對指定場景／事件的圖號做條件分支；對話是後續 opcode 1 的效果。因三個圖號欄位同時改動，尚不能判定哪一欄參與比較、是否只需任一欄相符。兩案合成的隊伍角色 58 在對話關閉後仍可於候選隊伍紀錄讀到；這**不**完成 opcode 21 的語意驗證。其他圖號、場景／事件索引、相對跳轉公式及自然故事可達性仍未驗。每案測後關閉唯一程序，第三槽六檔恢復基線 SHA-256。
