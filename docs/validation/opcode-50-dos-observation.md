# 原版 DOS 事件 460→675→676 與指令 50 局部驗證

2026-11-12。Phase 1／2。狀態：**局部原版執行證據**。所有畫面及記憶體來自 DOSBox-X 2026.10.01 的隔離 `session-002`；場景入場與部分背包前置是明確標記的 Synthetic State。不能據此宣稱自然遊戲進度可抵達全部場景，或 0–67 指令已驗收。

## 起點與可逆修改

- 原始 `R1/S1/D1` 不修改。只用隔離副本第三槽；每次合成前複製六個 R3/S3/D3 GRP/IDX 到 `assets/generated/dosbox-x/session-002/synthetic-*/original-slot3`，以 `manifest.json` 記錄 SHA-256、byte offset、改前／改後值。
- `R3.GRP` offset 4/6 經遊戲內存檔差分與位置畫面交叉核對，依原版資料順序讀為 `My/Mx`。場景 23 入口紀錄 offset 98292/98294 為 `Y=168/X=210`，場景 32 為 `Y=286/X=156`。從入口相鄰格向入口按 Up 後切場景。兩場景入場條件原值均為 1；本案僅在隔離副本將各自條件欄位設 0，故屬強制入場測試。
- S 檔第 3 層各場景事件槽 0 的唯一格位，場景 23 為 `(x=33,y=25)`、場景 32 為 `(x=25,y=31)`；在隔離 R3 改場景記錄的室內起點至相鄰可通行格。載入與畫面確認後，面向 NPC 按 Enter。
- DOSBox-X 的 emulator state 保存能產生檔，但 SDL1／SDL2 的載入曾崩潰；本案使用原版遊戲內第三槽及隔離副本。每次只保持一個遊戲程序。輸入至少間隔一秒，遇非預期狀態先擷取該遊戲畫格。

`R3.GRP` 候選物品表從 byte 36 開始，每組為 little-endian signed int16 ID／數量。正例注入位址 52–70；執行中唯一會變動的背包候選副本由五項各 1 變成空槽，後得 ID 176／數量 1。另一份相同前綴的記憶體副本保持載入時數值，故不能把任一搜尋命中直接認定為活躍背包；本案以同一程序操作前後變化及畫面交叉確認。非暫停唯讀工具為 `tools/analyzer/scan_dosbox_process_memory.py`；對 PID／HWND 的身份查核及輸入紀錄位於本機操作紀錄。

## 邊界與後續

- 上述 `0x...` host 位址隨程序啟動改變，不是 DOS guest 的穩定位址。完整背包、隊伍、角色屬性與武功位址仍待逐欄確認。
- OP50 的指定案例矩陣已實測：全缺、全有、五種單項缺失、單一零數量、單一額外物品及反向排列。這些局部案例不足以聲稱所有物品 ID、數量、重複槽、非法值或其他事件參數組合皆已驗證。
- Opcode 15、其他多數 opcode 的 DOS 語意尚未逐項驗證；本案只可更新 1／2／3／32／50 的**局部案例**，其中 2／32 的效果出現在 676 複合事件，不等於隔離測出該指令的全部語意。
- 合成入場條件不代表原版正常通關路線。原版入場條件值 1 的實際解鎖規則，以及 scene 23／32 自然可達性仍 Unknown。
- 禁止提交商業遊戲圖像、存檔或合成 GRP；截圖與 manifest 保留在 ignored 本機路徑。文內只記錄必要數值與 SHA-256。
