# 原版 DOS 畫面淡出與音樂切換的分離觀察

2026-11-13。Phase 1／2 局部原版執行證據。原始事件 531 位於 KDEF byte 82440，SHA-256 `6e203fe9ed597f8fc2c89a3f52f760f114a59574ae829caf258b4a28dea04ff3`。在指定物品 ID 183 的路徑，三段對話後依候選切分接 `14`、`66(9)`、`13`、對話 ID 1967。對照事件 514 位於 KDEF byte 78876，SHA-256 `1d0fc55ccbb18ed9e2219de375c6fca58917b04a5b14916550928b5a787a73b9`，含 `14`，沒有 `66`。原始 KDEF 均未改。

事件 531 在隔離 `session-002` 第三槽加入 ID 183 ×1，從原版物品頁使用，互動後順序推進三段對話，每次按鍵間隔至少 1 秒。`z_940.raw1.png` 仍顯示第三段對話；下一張 `z_941.raw1.png` 顯示同一室內整體明顯變暗；三秒後 `z_942.raw1.png` 顯示下一段「這…這是真的嗎？」對話。這支持本案例 opcode 14 在對話後使畫面短暫淡出；畫格沒有逐幀覆蓋完整淡出動畫，不能推定幀數與時間。

同一案例用 DOSBox-X 原生 Capture 選單錄製遊戲輸出 `z_001.wav` 與重跑的 `z_002.wav`，均為 48 kHz、16-bit、雙聲道。兩次錄音的第 0–39 秒每秒 RMS 大致為 1.9–2.4 千，第 40 秒起下降至約 0.6–1.2 千，並維持到停錄；重跑錄音 `z_002.wav` 長 46.646 秒，SHA-256 `41fb7c24235b59d219ce0eb65a578327e1864d491983f546de64eed0476d8a44`。聲音轉變發生在淡出／`66(9)` 段，後續對話證明事件已越過該段。

為區分淡出與音樂效果，另以事件 514 錄製只經過 `14` 而不含 `66` 的 `z_003.wav`；前後對話畫格為 `z_949.raw1.png`、`z_950.raw1.png`。此錄音長 13.325 秒，SHA-256 `44c26d44c808387889f5a36fd448d9392c4d30443a33c90ac22f92b8c7b19784`；13 個完整秒的 RMS 均在約 1.9–2.4 千，沒有事件 531 那種持續下降。對照支持事件 531 的持續音訊切換與 `66(9)` 有關，並非單靠 `14` 淡出造成。

只確認這兩個原始事件的局部畫面／音訊效果；不能從音量數值判定曲目 ID 9 對應哪一個音樂檔，也未驗其他場景與參數。合成事件指向與物品屬 Synthetic State，自然流程可達性未驗。兩次事件 531 與事件 514 的 result JSON、manifest、原生錄音及畫格存於 ignored `assets/generated/dosbox-x/session-002/`；每案精確關閉 DOSBox-X 程序，六個第三槽檔案逐檔核對已還原。
