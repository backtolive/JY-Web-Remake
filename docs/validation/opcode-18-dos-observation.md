# 原版 DOS 指令 18 的物品條件對照

2026-11-12。Phase 1／2，局部原版執行證據。使用 DOSBox-X 2026.10.01 的隔離 `session-002`，未修改 KDEF 或原始商業資料。遊戲畫格保留在 ignored 的 `assets/generated/dosbox-x/session-002/capture`。

## 原始事件與合成前置

原始事件 37 位於 KDEF，SHA-256 `9dffd5525639978f026ae57f9f087c8d00e96962a5c841a9db9f25a6021feb09`。候選指令以 `18(173,0,15)` 開始，後續兩條可達路徑分別包含事件欄位修改／返回，或對話 139。這個候選切分來自 FishEdit 長度表，尚非 DOS 指令位址 trace。

從事件 460 後的原版遊戲內第三槽存檔建立兩份可逆 Synthetic State：均強制由世界地圖進入場景 32，將 NPC 槽 0 的事件指向原始事件 37；其中一份在背包加入 `(173,1)`，另一份不加入。六個 R3/S3/D3 槽檔備份、雜湊與每個 byte offset 見本機 ignored 的 `synthetic-op18-event37-present-20261112/manifest.json`、`synthetic-op18-event37-absent-20261112/manifest.json`。

## 執行對照

| 前置 | 觸發前唯讀記憶體 | 觸發後畫面與同一事件槽 | 結論範圍 |
|---|---|---|---|
| 有 ID 173 ×1 | 背包含 `(173,1)`；場景 32／槽 0 前五個 word 為 `[1,0,37,-1,-1]` | 返回室內；同一 host 位址的事件 ID 由 37 變 `-1`，圖像欄位也變動。畫格 `z_214.raw1.png` | 有物品時走到修改事件槽的路徑，與候選 `18` 真分支及後續 `3` 相符。 |
| 無 ID 173 | 背包不含 173；場景 32／槽 0 前五個 word 同為 `[1,0,37,-1,-1]` | 顯示另一段主角對話；事件 ID 仍為 37。畫格 `z_219.raw1.png` | 缺物品時走到不同路徑，與候選 `18` 假分支及對話 139 相符。 |

兩案例分別使用唯一 DOSBox-X PID/HWND。記憶體透過 `ReadProcessMemory` 唯讀取得，遊戲未凍結；host 位址只對當次 PID 有效。互動前確認室內畫面已載入；未將最初世界地圖階段搜尋不到事件槽誤作原版結果。

## 限制

本案支持「事件 37 的 opcode 18 依背包是否有 ID 173 分流」的原版局部行為。事件槽清除屬後續 opcode 3 的效果；對話屬後續 opcode 1 的效果，不能歸給 opcode 18 自身。數量 0、重複槽、非法 ID、第二個 opcode 18（事件 38）及跳轉 offset 的精確 DOS 解碼仍未驗證。
