# 原版 DOS 事件 931 的住宿選擇與 HP 恢復

2026-11-12。Phase 1／2，局部原版執行證據。事件 931 位於 KDEF byte 112604，長 42 bytes，SHA-256 `f5041f4174e01ca6a5bda54567e9ef84032cec75200cd634848b8e2d18c5d072`。原始 words 開頭為 `11(1,0),7,1(2843,0,1),0,14,12,40(3),0,13,1(2844,0,1),0,-1`；KDEF 未修改。此為候選切分，精確跳轉公式未以指令 trace 證實。

隔離 `session-002` 第三槽把場景 32 槽 0 指向事件 931，合成解鎖場景並從世界圖入場。DOSBox-X 2026.10.01 顯示 `是否在此借宿過夜 (Y/N)`（`z_397.raw1.png`）。送 `N` 後直接回到室內（`z_398.raw1.png`）；重新互動仍顯示同一提示（`z_399.raw1.png`）。送 `Y` 後出現住宿對話（`z_400.raw1.png`），接續顯示隔天起床對話（`z_401.raw1.png`）。此 Y／N 畫面對照支持 opcode 11 在此事件取鍵盤選擇並分支；後續對話屬 opcode 1。

另一次只將隔離第三槽主角候選 CurrentHP 從 44 改為 1；DOS 讀檔後唯讀執行中主角記錄確為 `1/44`。同一事件送 Y 後、第一段對話仍開啟時 HP 為 `1/44`（`z_407.raw1.png`）；關閉第一段對話後、第二段對話顯示時，同一 host 記憶體位址變為 `44/44`（`z_408.raw1.png`）。原始腳本兩段對話間包含 opcode 12；此局部差分支持其 HP 恢復效果。opcode 14／40 亦在這段腳本中，但本案沒有單獨隔離它們的畫面或狀態效果。

合成狀態的原值、byte offset、before／after SHA-256 與備份見 ignored 的 `synthetic-op11-event931-20261112`、`synthetic-op11-event931-hp1-20261112` manifest。每次只使用一個精確 DOSBox-X PID／HWND，測後關閉並還原六個第三槽檔案至基線雜湊。自然住宿可達性、N/Y 分支在其他事件的偏移公式、opcode 12 對同伴／MP／體力／中毒／受傷的完整規則均未驗證。
