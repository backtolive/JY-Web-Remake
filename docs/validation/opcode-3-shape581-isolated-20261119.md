# 事件 581 參數形狀的單指令 DOS 對照 — 2026-11-19

證據類別：**Synthetic Script / Verified Original DOS interpreter behavior**。這次執行的是隔離遊戲副本的合成腳本，不是原始事件 581 的完整劇情路徑。

原始事件 581 的候選 word 15 為 `3,-2,2,0,0,-1,-1,-1,-1,-1,-1,-2,-2,-2`；來源 KDEF 記錄位於 byte 88988，SHA-256 `ac27f3fee143440e3d3af716d1b460e703959545f58d7f93a604c3a7f5e74386`，詳見[來源比對](event-581-slot-comparison-20261119.md)。本輪將**同一組 13 個參數**單獨寫入隔離 KDEF 的事件 464，後接 opcode 7 結束；相鄰的 14、0、13 均不在合成腳本內。隔離 KDEF 原始 SHA-256 `135c5e097a7fe561ee931046e1bebf55de9b469678e3d111d8e9f2c6bb600e06`，合成版為 `63c90fca03b5efec4afc7cc3a2c181d58bf510c75f602baf69245113e44212df`。補丁 manifest 留在被 Git 忽略的 `assets/generated/dosbox-x/op3-shape581-isolated-20261119/manifest.json`。

以隔離第三槽載入場景 32，將事件格指向合成事件 464；目標槽 2 的欄 3／4 預設值特別改為 `123／456`，用來區分「寫入 -1」與「保留原值」。同一 DOSBox-X PID 7508、遊戲 HWND `0x38085A`，從場景內以 `Left`、`Enter` 觸發。唯讀讀取同一活躍記憶體位址 `0x22e964506fc` 的 11 個 16-bit 欄位：

| 時點 | 場景 32／槽 2 欄 0–10 |
|---|---|
| 觸發前 | `[1,2,-1,123,456,2718,2718,2718,0,30,21]` |
| 觸發後 | `[0,0,-1,-1,-1,-1,-1,-1,0,30,21]` |

因此，**這一組具體參數**在原版 DOS 解譯器內可單獨將欄 0／1 寫為 `0／0`，欄 3／4 寫為 `-1／-1`，欄 5–7 寫為 `-1`；欄 8–10 保持原值。欄 2 的前後值都是 `-1`，無法從此差分判定該欄是寫入還是保留。這個結果排除了原始事件 581 相鄰指令對**上述已變欄位**的必要性，也和先前單人隊伍的完整段落終態一致；它不證明其他 105 個同形事件都可達、也不定義任意參數值下的通用 opcode 3 規則。
