# opcode 55 追蹤前置：確認事件真的被觸發

2026-11-14。Phase 1／2；Status: **最短合成腳本的本輪觸發未成功，opcode 55 語意仍未驗收**。沿用 DOSBox-X 2026.10.01、唯一 PID 7508、遊戲 HWND `0x38085A`，所有寫入僅在 ignored `session-002/game` 隔離副本並由 manifest 備份。原始 KDEF 與第三槽於結束時均還原。

## 證據

- 隔離 `S3.GRP` 場景 32 的事件層 3，事件槽 0 唯一格是 `(x=25,y=31)`，槽 1 在 `(25,32)`。隔離 `D3.GRP` 槽 0 的前五個 word 為 `[1,0,1017,-1,-1]`；`--spawn-near-event 0` 將候選入口座標寫成 `(25,32)`。這些是檔案值，**不能單獨證明執行中的角色站在該格**。
- 先前以全部 11 個 word 搜尋事件槽，角色靠近時圖號欄由 7448 改為 7484／7464 等，即使事件 ID 仍為 1017 也回報 0 個匹配。改用前五個 word 後，事件 ID 1017 仍可找到。因此「整筆紀錄消失」不等於事件已執行。該圖號變動與走動／動畫同時出現；未把它歸給任何 opcode。
- 本輪將事件 1017 暫時換成 `55,2,-1,3,0,2,57,1,7`。在多次 `Enter`、`Left+Enter`、候選面向值 2 的入場後，背包前 20 格仍無 ID 57，客體 `0x0028EE90` 事件緩衝區為零；32 MiB 全區快照也沒有該合成腳本的前 10 bytes。這些案例**沒有建立腳本執行前提**，所以候選載入器 `0160:001E136C`、分派器 `0160:001E1554`、55 表項 `0160:001E1ADF` 的未命中不能判定它們不是執行路徑。
- 一次穩定 `Right` 移動的前後快照中，客體 `0x00287958` 與 `0x0028795C` 皆 `+1`；反向 `Left` 恢復，另幾次 `Left` 被場景阻擋。這些位置可作**視野移動指標**，尚未證明是玩家的精確格座標。`--save-header` 匹配的 `(45,29)` 與第一槽存檔 bytes 相同，是載入副本，不能用作活躍玩家位置。
- 使用工具既有的「直接室內」合成分支，把存檔首部候選場景寫成 33，載入後的精確遊戲畫面卻停在世界地圖；該欄位在本原版程序中不能作已驗證的室內跳轉。候選面向欄 offset 12 值 2 也未建立事件觸發。

本輪新增 `prepare_synthetic_event_slot.py --set-player-facing`，只記錄並修改隔離第三槽 offset 12 的社群候選 MFace；**未驗證原版面向語意**。所有測試斷點已清空，KDEF SHA-256 回到 `135c5e097a7fe561ee931046e1bebf55de9b469678e3d111d8e9f2c6bb600e06`，R3／D3 回到 `aa2f4dee1b6b73120ebe92a100535e30c7d608cb0d2b0dd38ffa900d9f47c22c`／`8ec61fa55fcdf698223534753b19e453f7d14f9510c3361ef4641e53ffec9d56`，PID 7508 仍開啟。

下一步要先建立事件觸發守門：使用原版畫面、物品或腳本緩衝區的**正向**變化，並記錄每次鍵盤操作與角色位置；只在觸發已成立的同一次運行才解讀 breakpoint。先前[合成 55 道具結果](opcode-55-dos-branch-probe-20261114.md)仍是已記錄的輸出，但其控制流歸因須待可重現的觸發路徑核對；不要以本輪未觸發案例推翻那些輸出。

後續已用**不改面向／第二入口**的舊配置重現 `Up → Left → Enter` 觸發、ID 57 ×1、opcode 55 入口停點。此頁上方的「未觸發」只描述當時配置，當前結論見[正向觸發 trace](opcode-55-verified-entry-trace-20261114.md)。
