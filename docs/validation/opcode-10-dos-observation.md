# 原版 DOS 事件 581 的虛竹加入隊伍

2026-11-12。Phase 1／2，**局部原版執行證據**。原始事件 581 位於 KDEF byte 88988，資源 SHA-256 `ac27f3fee143440e3d3af716d1b460e703959545f58d7f93a604c3a7f5e74386`。候選尾段依序含 `46(49,300),48(49,200),47(49,30),45(49,20),33(49,15,0),49(49,2),10(49),-1`。本案確認此路徑結束後角色 49 進入執行中隊伍；仍不把所有參數變體視為驗收完成。

在隔離 `session-002` 第三槽合成一人隊伍、場景 32 槽 0 指向事件 581。原始首段對話後，固定場景的畫格差異工具連續讀到四個上方通知覆蓋層（`z_450–453.raw1.png`），其後兩格 `z_454–455.raw1.png` 無覆蓋層。再送一次 Enter 出現與首段對話像素相同的下方對話（`z_456.raw1.png`）；表示事件已返回可再次互動的狀態。只在第一個通知矛盾時人工檢視 `z_450`，文字為「虛竹 內力增加 300」。

修正角色表後，原版 R3 段界 `836..59075` 可分為 **320 筆 × 182 bytes**；角色 49 姓名為「虛竹」。在新的一人前置重播中，同一執行中角色 49 紀錄從 HP `38/38`、MP `21/21`、攻擊 `14`、速度 `30`，變為 HP `238/238`、MP `321/321`、攻擊 `44`、速度 `50`。五個能力通知後覆蓋層清除（`z_459–464.raw1.png`）。這些差異吻合尾段的 46／48／47／45 候選參數，支持腳本確實走過能力變更。

先前 `--team` 錨定到載入存檔副本，通知後仍顯示 `[0,-1,-1,-1,-1,-1]`，**不能代表執行中隊伍**。全程序唯讀搜尋六個角色 ID 的連續陣列，找到唯一 `[0,49,-1,-1,-1,-1]` 候選，地址 `0x17a095fbbb8`，後接與世界座標相符的數值；同一程序的存檔副本在另一地址。此差異支持尾端 `10(49)` 將虛竹加入執行中隊伍。事件 581 的尾段沒有其他隊伍修改候選指令。host 地址只適用該 PID，不是固定 guest offset。

先前錯誤的 208-byte 角色間距把「黃蓉」誤讀成角色 49，相關「內力沒有增加」推論已撤回。兩次合成前置與備份見 ignored 的 `synthetic-op10-event581-20261112/manifest.json`、`synthetic-op10-event581-correct-role-layout-20261112/manifest.json`。每案關閉唯一精確 DOSBox-X 程序後六檔 SHA-256 均還原基線。尚未獨立驗證角色 49 攜帶物品轉移、隊伍滿額時 opcode 10 的行為、其他角色或自然流程可達性。
