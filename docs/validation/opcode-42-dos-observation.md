# 原版 DOS 事件 445 的隊伍性別分支

2026-11-12。Phase 1／2，局部原版執行證據。原始事件 445 位於 KDEF byte 69100，長 362 bytes，SHA-256 `c6afc0e5ec29690a9ea2353d5d1c218cd3fa96c9b916e1c6feb2b96ff1e5e64f`。候選腳本在加入 Y/N 的 Y 路徑共同對話後有 `42(6,0)`，其後兩條路徑給不同對話。KDEF 未修改。

隔離 `session-002` 第三槽將場景 32 槽 0 指向事件 445，合成解鎖入場；兩案只改主角原版角色記錄相對 offset 28 的候選性別值 `0`／`1`。DOSBox-X 在兩案都顯示加入 Y/N，均選 Y 並關閉共同對話；進入 opcode 42 後，值 0 的畫格 `z_477.raw1.png` 顯示角色拒絕並要求先找到女性同伴，值 1 的 `z_481.raw1.png` 顯示答應同行。兩個後續畫格的對話區像素差明顯（top 0.1572、center 0.212），人工各讀一次確認文字不同。

因此本案例支持 opcode 42 依主角候選性別值選擇後續分支，且原版對話內容與有無女性隊員相關。**沒有測試男性主角搭配女性同伴**，不能據此把 opcode 42 的完整條件定義為「檢查隊伍任一女性」。也未驗 `6,0` 的完整相對跳轉公式、戰鬥中的性別效果及自然流程可達性。

兩案合成修改、byte offset、原值、SHA-256 與備份見 ignored 的 `synthetic-op42-event445-sex0-20261112/manifest.json`、`synthetic-op42-event445-sex1-20261112/manifest.json`。每案關閉唯一精確 DOSBox-X 程序後隔離第三槽六檔回到基線雜湊。
