# 原版 DOS 事件 676 的 opcode 44 動畫

2026-11-13。Phase 1／2；Status: **局部 DOS 行為確認**。原始 KDEF 事件 676 byte offset 101062，SHA-256 `8a8e73c5f766a92a30e5bba86aa53f99b321958d7450922744e5c1e3090eb07a`。材料齊備分支先把場景 32 槽 2／3 的圖號初始化為 7536／7580，接著連續三次 `44(2,7536,7578,3,7580,7622)`，最後才由 opcode 3 設定終態 2718／2720。

在唯一 DOSBox-X PID 7508 內，從標題頁讀取隔離第三槽。五件測試物品 ID 138–142 各一，事件槽 0 唯讀為 676；只送一次入場 Up，再 Left＋Enter。遊戲顯示材料齊備的原始對話，活躍背包副本的五件物品全數清空，另一份載入時副本不變。這排除了前一案只有場景待機畫面的誤判。

關閉最後對話前，槽 2／3 三個圖號欄均為 2718／2720；啟動原生 AVI 後送 Enter。約六秒後仍在動畫段時，同址唯讀槽 2／3 的三個圖號欄分別為 **7560／7606**。這兩值位於候選 opcode 44 的兩段範圍 7536–7578、7580–7622 之內，且不等於前後 opcode 3 所設定的起點或終態。稍後兩槽回到 2718／2720。影片 `z_004.avi` 4,526,286 bytes、465 個 ZMBV 畫格；研究用 decoder `tools/analyzer/inspect_zmbv_avi.py` 取出的 `frame-00180.png` 可見廚師移向爐灶，`frame-00360.png` 位於爐灶旁。原始影片及解碼影格均在 ignored capture 目錄，未提交商業素材。

此案例支持 **opcode 44 同時推進兩個場景事件的動畫圖號並重畫畫面**。三次調用各自的精確時長、每幀增量與其他參數組合尚未逐一測量。前一段 `z_003.avi` 是未觸發事件的待機影片，不能作 opcode 44 證據；見[限定採樣及更正](opcode-13-44-65-bounded-20261113.md)。
