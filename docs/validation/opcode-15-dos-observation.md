# 原版 DOS 指令 15 的敗北路徑觀察

2026-11-12。Phase 1／2，局部原版執行證據。使用 DOSBox-X 2026.10.01 的隔離 `session-002`，沒有修改 `KDEF.GRP/IDX` 或商業原始檔。所有畫格留在 ignored 的 `assets/generated/dosbox-x/session-002/capture`。

## 事件與前置

原始事件 190 位於 KDEF byte 26454，長 136 bytes，SHA-256 `8c547e22add7b8c15ced1dd46be848f1caa5a7e3edd594462b982675674b7fdd`。候選指令序列以 `1, 0, 6, 15, 7` 開始；指令 15 後的原始 word 為 83。事件 6 的戰鬥參數以 battle ID 28 開始，敗北候選路徑緊接 `15,83`，成功路徑跳過它。

只在隔離第三槽合成前置：由事件 460 後的遊戲內存檔複製，強制場景 32 入場，將該場景槽 0 的事件 ID 由 675 改為 190，並把主角候選 HP 欄位 `R3.GRP` byte 870 由 44 改為 1。每個 offset、前後值及六個槽檔 SHA-256 記於 `synthetic-op15-event190-20261112/manifest.json`。這證明的是**原始事件腳本在合成前置下的執行**，不證明自然劇情會在此 NPC 觸發事件 190。

## 兩次重播

1. 在精確 DOSBox-X 遊戲 HWND/PID 上由標題畫面載入進度三，從世界地圖進入場景 32，等室內轉場完成再面向 NPC 互動。原始事件 190 的開場對話見 `z_164.raw1.png`。
2. 選主角參戰；戰鬥畫面顯示生命 `1/44`，見 `z_168.raw1.png`。選「自動」後出現「戰鬥失敗」，見 `z_173.raw1.png`；按 Enter 後顯示「死亡」印章及載入進度選項，見 `z_174.raw1.png`。
3. 從該結束畫面直接再載入同一第三槽，重播相同事件、戰鬥及自動操作。再次出現「戰鬥失敗」及死亡／讀檔頁，見 `z_181.raw1.png`、`z_182.raw1.png`。第二次沒有改動存檔或事件腳本。

## 對照及結論邊界

- 原始事件 0 的指令為 `0,-1`。將同一 NPC 在隔離 D3 指向事件 0 後互動，仍留在室內並可接受移動輸入；畫格 `z_187–188.raw1.png`。因此單獨的 `-1` 不是「破關結局」的充分條件。
- 原始事件 16 的候選前段為 `4(160,1,0),7,...`。未使用指定物品而互動後直接回到室內，見 `z_193.raw1.png`；這與 opcode 7 返回事件相符。但沒有指令位址 trace，故不把此案例當作隔離的 opcode 7 語意證明。
- 原版實測支持事件 190 的**敗北路徑**導向死亡／讀檔頁，且可重播。候選腳本與社群來源均指出 opcode 15 為該路徑的關鍵，但本次沒有 DOS EXE 指令 trace，不能單獨證明 83 的作用、opcode 15 是否消耗此 word，或 7 是否曾執行。不要將 83 推為結局編號，也不要把這一敗北案例外推到全部 114 次出現。

後續已在隔離最短 `15,83,7` 腳本命中原版 handler，確認它會**讀取並傳遞 `83`**；詳見[二進位限定 trace](opcode-15-83-binary-trace-20261114.md)。本頁原始事件 190 的敗北畫面與這項後續證據應分別看待。
