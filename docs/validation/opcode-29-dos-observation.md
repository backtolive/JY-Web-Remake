# 原版 DOS 指令 29 的攻擊力分支

2026-11-12。Phase 1／2，局部原版執行證據。原始事件 640 位於 KDEF byte 98952，長 98 bytes，SHA-256 `01b01c629a02602b0511b30dd4e5f4d6420e196b8c5f88938377b06a9022eb7c`；開頭候選切分為 `29(0,75,1000,11,0)`。KDEF 未修改。依原始 words，word 6 是 opcode 27，word 11 是對話，word 16 是 opcode 7；word 17 起有 opcode 3、兩次 opcode 27、對話及 opcode 2。此為靜態定位，不能單獨證明跳轉公式。

以 DOSBox-X 2026.10.01、隔離 `session-002` 第三槽重播。兩次均將場景 32 候選入場條件 1→0、入口設在事件格南側、事件槽 0 腳本指向未修改的原始事件 640；僅攻擊力候選值不同。每次從世界圖確認切到室內，對準 NPC 後互動；所有改動、原值、SHA-256 與備份記於 ignored 的 `synthetic-op29-event640-distance1-left-attack28-20261112` 與 `synthetic-op29-event640-attack75-20261112` manifest。每案只使用一個精確 PID／HWND，測後關閉並還原六個第三槽檔案至基線雜湊。

| 主角候選 Attack | 原版觀察 | 局部結論 |
|---:|---|---|
| 28，第三槽來源原值 | 執行中角色記錄相對 word 43 為 28；`z_379.raw1.png` 顯示主角表示力氣不足；穩定事件槽腳本仍為 640；背包無 ID 110。 | 走不足條件的對話路徑，與候選偏移 0 相符。 |
| 75，Synthetic State 單變量 | 執行中角色記錄相對 word 43 為 75；`z_383.raw1.png` 時事件槽 `[1,0,640,-1,-1,…]` 改為 `[1,1,-1,-1,-1,…]`；`z_384.raw1.png` 顯示拔劍對話；關閉後 `z_385.raw1.png` 顯示取得金蛇劍，執行中背包由無 ID 110 變為 `(110,1)`。 | 走另一條路徑；事件修改與取得物品是後續 opcode 3／2 的效果，不歸給 29 自身。 |

本案支持 opcode 29 對主角候選 Attack 值 28／75 做分支，且 75 是此事件的有效下界。未驗證上界 1000、其他角色／事件、MOD 變體、原版完整相對跳轉公式及自然流程可達性。場景解鎖、入口與事件指向均為 Synthetic State。

採樣校準：首次東側直走被原始建物占格擋住；未解鎖時入口不切圖。載入第三槽後須確認世界圖已完成，才送入場鍵；載入過程中過早送鍵的一次嘗試沒有入場。室內進場頁與互動格位均須實際確認，不能把已排隊的 Enter 當腳本執行證據。這些失敗嘗試沒有用來推導 opcode 語意。
